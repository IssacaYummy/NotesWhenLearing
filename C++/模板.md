范型编程技术支持程序员创建函数和类的蓝图(即模板，template)，而不是具体的函数和类

这些模板可以没有任何类型：它们可以处理的数据并不限于某种特定的数据类型

当程序需要用到这些函数中的某一个时，编译器将根据模板即时生成一个能够对特定数据类型进行处理的代码版本。

范型编程技术可以用一个解决方案解决多个问题

在范型编程技术里，我们仍然需要编写自己的函数和类，但不必限定他们所使用的数据类型

只需要使用一个占位符（通常用字母T来表示），然后用这个占位符来编写函数

当程序需要这段代码时，你只需提供数据类型，编译器将根据你的模板即时生成实用的代码

简单的说编译器把模板里的每一个T替换为所提供的数据类型

STL(Standrad Template Library)库是范型编程技术的经典之作，它包含可许多非常有用的数据类型和算法

## 函数模板

以下代码定义了一个名为foo()的函数模板：

```C++
template <class T>
Void foo(T param)
{
    //do something
}
```

第一行代码里，在尖括号里有一个class T，用来告诉编译器：字母T将在接下来的函数里代表一种不确定的数据类型

关键字class并不意味着这个是类，只是一种约定俗成的写法

在告诉计算机T是一种数据类型之后，就可以像对待普通哦个数据类型那样使用它了

在创建模板时，还可以用template<typename T>来代替template<class T>，他们的含义是一样的

如果某个函数对所有数据类型都将进行同样的处理，就应该把它编写为一个模板

如果某个函数对不同的数据类型将进行不同的处理方式，就应该对它进行重载

  

## 类模板

类模板与函数模板非常类似：同样是先由我们编写一个类的模板，再由编译器在我们第一次使用这个模板时生成实际代码

示例

```C++
template<class T>
class MyClass
{
    MyClass();
    void swap(T &a, T &b);
    
}

//构造器实现
MyClass<T>::MyClaass()
{
    //init
}
```

因为MyClass是一个类模板，所以不能只写出MyClass::MyClass，编译器需要我们在这里必须在尖括号里给出一种与MyClass()配合使用的数据类型。因为没有确定的数据类型可以提供，所以使用一个T作为占位符即可

## 内联

### 内联函数

内联函数是一个由 `inline` 关键字修饰的函数。它是一种对编译器的建议（只是建议，不是命令），建议编译器在调用该函数的地方，用函数体本身的代码来替代函数调用。

```Java
// 普通函数
int max(int a, int b) {
    return a > b ? a : b;
}

// 内联函数
inline int inlineMax(int a, int b) {
    return a > b ? a : b;
}

int main() {
    int x = 10, y = 20;
    // 普通函数调用：会产生函数调用开销
    int z1 = max(x, y); 

    // 内联函数：编译器处理后会“近似于”将代码直接贴在这里
    // int z2 = (x > y ? x : y);
    int z2 = inlineMax(x, y); 

    return 0;
}
```

编译器在处理 `inlineMax(x, y)` 时，可能会将 `main` 函数生成类似下面的代码：

```Java
int main() {
    int x = 10, y = 20;
    int z1 = max(x, y); // 这里仍然是 call 指令

    // 内联展开后
    int z2; // 没有 call 指令
    // 下面是函数体的代码直接嵌入
    if (x > y) {
        z2 = x;
    } else {
        z2 = y;
    }

    return 0;
}
```

### 内联函数工作原理

1. 编译阶段：当编译器遇到一个被 `inline` 修饰的函数调用时，它会根据一系列启发式规则（后面会讲）来决定是否采纳这个建议。
    
2. 决策：如果决定内联，编译器就会将函数体的代码复制到调用点，同时用实参替换形参。
    
3. 链接：内联函数通常需要在每个使用它的编译单元（通常是 `.cpp` 文件）中都可见。因此，内联函数通常直接定义在头文件（.hpp/.h）中。如果定义在 `.cpp` 文件中，那么其他 `.cpp` 文件就无法看到它的定义，也就无法进行内联展开。（在 C++17 中，`inline` 变量也用于解决类似的多定义问题）
    

  

  

内联模板和函数模板的创建过程几乎没有什么区别

不管是什么模板，编译器都哦必须看到全部代码才能为一种给定的类型创建出一个新的实现来

在创建类模板时，避免类声明和类定义相分离的一个好方法时使用内联方法

在类里，内联方法的基本含义是在声明该方法的同时还对他进行定义

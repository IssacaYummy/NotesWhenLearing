和 OpenVINS 一样，**先在 PC 上跑数据集，再上香橙派，最后接飞控**。

## 第 1 步：在 PC 上编译（Ubuntu 22.04 + Humble）

```bash
sudo apt install -y ros-humble-cv-bridge ros-humble-image-transport \
  libgoogle-glog-dev libgflags-dev libatlas-base-dev libeigen3-dev libsuitesparse-dev

# Ceres 2.1.0 源码编译
cd ~ && git clone <https://ceres-solver.googlesource.com/ceres-solver>
cd ceres-solver && git checkout 2.1.0 && mkdir build && cd build
cmake .. -DBUILD_TESTING=OFF -DBUILD_EXAMPLES=OFF && make -j$(nproc) && sudo make install

mkdir -p ~/vins_ws/src && cd ~/vins_ws/src
git clone <https://github.com/JanekDev/VINS-Fusion-ROS2-humble-arm.git>
```

**编译前改一处**：打开 `vins/src/featureTracker/feature_tracker.h`，把第 14 行左右的 `#define GPU_MODE 1` 注释掉，改用 CPU 版。GPU 版依赖带 CUDA 的 OpenCV[[1]](https://github.com/JanekDev/VINS-Fusion-ROS2-humble-arm)，香橙派用不上。

```bash
cd ~/vins_ws && colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release
```

⚠️ 仓库里的 `install_external_deps.sh` 会从源码编译 OpenCV，**先看看它做了什么，别直接运行**。自己再编一份 OpenCV，很容易和 ROS 自带 `cv_bridge` 用的 OpenCV 4.5 冲突。apt 装的那套就够用了。

## 第 2 步：用 EuRoC 跑通，并和 OpenVINS 对比

```bash
pip install rosbags evo
rosbags-convert MH_01_easy.bag --dst ~/data/MH_01_easy      # ROS1 bag 转成 ROS2 格式

# 终端 A
ros2 run vins vins_node ~/vins_ws/src/VINS-Fusion-ROS2-humble-arm/config/euroc/euroc_stereo_imu_config.yaml
# 终端 B
ros2 launch vins vins_rviz.launch.xml
# 终端 C（同时录下输出，方便评估）
ros2 bag record /odometry -o vins_mh01 &
ros2 bag play ~/data/MH_01_easy
```

用 evo 算 ATE，和你之前 OpenVINS 在同一条序列上的结果对比。**过关标准**：轨迹平滑，ATE 和 OpenVINS 在同一量级。

## 第 3 步：编译到香橙派

步骤和第 1 步一样。内存小的话，先加 4 GB swap，再单线程编译：

```bash
MAKEFLAGS="-j2" colcon build --parallel-workers 1 --cmake-args -DCMAKE_BUILD_TYPE=Release
```

## 第 4 步：为 D430 + 飞控 IMU 写配置

新建 `config/d430/`，复制 EuRoC 的 stereo_imu 配置，然后修改。

**`d430_stereo_imu.yaml` 需要改的项**

```yaml
imu_topic: "/imu"            # 改成 sensor_combined_to_imu 实际发布的话题
image0_topic: "/camera/camera/infra1/image_rect_raw"
image1_topic: "/camera/camera/infra2/image_rect_raw"
cam0_calib: "cam0_pinhole.yaml"
cam1_calib: "cam1_pinhole.yaml"
image_width: 848
image_height: 480
estimate_extrinsic: 1        # Kalibr 结果当初值，稳定后可改为 0
body_T_cam0: ...             # 见下方说明
body_T_cam1: ...
max_cnt: 120                 # 香橙派算力有限，先少一点
freq: 15
multiple_thread: 1
acc_n / gyr_n / acc_w / gyr_w: 取 Allan/Kalibr 的值，再放大 3～10 倍作为起点
estimate_td: 1
td: 0.00349                  # 来自 Kalibr 的 timeshift_cam_imu
show_track: 1
```

EuRoC 原配置里各字段的含义可以对照 zinuok 的文件[[4]](https://raw.githubusercontent.com/zinuok/VINS-Fusion-ROS2/main/config/euroc/euroc_stereo_imu_config.yaml)。

**三个最容易出错的地方**

1. **`body_T_cam` 要求逆矩阵。** Kalibr 输出的是 `T_cam_imu`（IMU→相机），VINS 要的是 `T_imu_cam`。直接填进去，VINS 一初始化就会飞掉。
2. **`td` 的符号。** VINS 的定义是“图像时间 + td = IMU 时间”，Kalibr 的定义是 t_imu = t_cam + shift，两者方向一致，所以直接填 0.00349。
3. **相机模型。** Kalibr 用的是 pinhole-radtan，就写成下面这样；如果用的是 equidistant，`model_type` 要改成 `KANNALA_BRANDT`。

```yaml
%YAML:1.0
---
model_type: PINHOLE
camera_name: camera
image_width: 848
image_height: 480
distortion_parameters: {k1: ..., k2: ..., p1: ..., p2: ...}
projection_parameters: {fx: ..., fy: ..., cx: ..., cy: ...}
```

## 第 5 步：手持测试

相机继续用你原来的终端 1 命令，**红外投射器保持关闭**。启动 DDS Agent 和 IMU 桥接节点，然后：

```bash
ros2 run vins vins_node ~/vins_ws/src/VINS-Fusion-ROS2-humble-arm/config/d430/d430_stereo_imu.yaml
ros2 topic hz /odometry
```

- 启动后先静止 3～5 秒，让 VINS 完成重力对齐。
- 先横向平移晃动一下，帮它初始化。
- 打开 `show_track` 的图像话题，特征点应该分布均匀，不能扎堆在中间。

**过关标准**：放在桌上不动时轨迹不漂；绕一圈回到起点，误差和 OpenVINS 差不多。

## 第 6 步：接入 PX4（`odom_to_px4` 要改）

1. **订阅话题**：从 `/ov_msckf/odomimu` 改成 VINS 的 `/odometry`。
2. **速度坐标系不同。** OpenVINS 的速度在机体系，而 VINS 原版的 `twist` 是**世界系**速度（来自 `estimator.Vs`）。这一点建议在你用的移植版 `visualization.cpp` 里确认一下。两种处理办法：
    - 最简单：先把 `EKF2_EV_CTRL` 改为 **11**，不融合速度，只用位置和偏航。
    - 或者：把速度按位置同样的方法转换成 `[vx, -vy, -vz]`，`velocity_frame` 改成 `2`（FRD 世界系），不再用 `3`（BODY_FRD）。
3. VINS 不填协方差，消息里是 0。你用的 `EKF2_EV_NOISE_MD=0` 会取参数作为下限，没有影响。
4. 验证方法和之前一样：用 `listener vehicle_visual_odometry` 和 `estimator_status_flags` 检查，或者直接看状态面板（面板里的话题名也要改成 `/odometry`）。

⚠️ **不要让 OpenVINS 和 VINS 同时往 `/fmu/in/vehicle_visual_odometry` 发数据**，否则 EKF 会收到两路互相打架的位姿。做对比时，一个发给飞控，另一个只录 bag。
